# Disk alerts and storage quotas

Storage limits are disabled by default. In Settings, configure a disk alert threshold and/or a disk quota for local storage or a saved remote destination. The form uses decimal GB (1,000,000,000 bytes); settings exports store integer bytes in `backupplus_storage_limits`, as `service => instance ID => {alert, quota}`. Local storage and providers without multiple instances use an empty instance ID. Blank or zero disables a limit. Save a newly added remote destination before setting its limits.

Each limit independently notifies the site administrator at 80% and 100%. A direct jump above 100% sends the critical level only. Notifications also appear in the Backup / Restore tab and do not depend on backup report preferences. Quota critical emails are limited to once per 24 hours and repeat daily while a successful measurement still finds the destination at or above quota. A successful measurement below a level rearms that level. Failed measurements retain the previous usage and alert state and show an unavailable/stale result.

A quota replaces count retention at its destination. At or above quota, the oldest eligible recovery sets are deleted until usage falls below quota. A set contains the full backup and all dependent increments; PITR sets also contain their manifests and locators. The newest complete chain for each source is protected at each destination, including additional file and database sources. Partial database coverage cannot replace a complete database backup. Locked and imported backups, pending update recovery points and active backup/restore dependencies are protected. If these prevent compliance, the excess remains and backups continue. A local quota also retains local archives after remote upload and restore, overriding the delete-local checkbox.

The monitor measures local files and remote listings, deduplicates artifact names, and falls back to recorded sizes when providers omit sizes. Work directories, temporary files and logs are excluded. Unknown sizes and failed listings cannot authorize eviction. Retention at destinations without quotas continues to use the configured database and file counts. With all quotas disabled, the existing retention implementation is used.

Monitoring runs after publication and hourly through `backupplus_storage_monitor`, independently of daily retention-cleanup mode. Interrupted work retries through `backupplus_storage_monitor_retry`. A process lock serializes monitors. Deletion intent and per-file receipts are checkpointed before and after provider calls; another destination's history and inventories remain available. Restore discovery hides destinations being removed and skips files already deleted there. The dashboard shows usage, limits, measurement time, severity and blocked/failed eviction details.

Deactivation removes monitor events. Removing/resetting the limits option also clears alert status. Deletion receipts stay with backup history because they describe where archives remain available.

Verification includes isolated unit fixtures, `scripts/check-storage-limits.php` in disposable WordPress sites, and `scripts/test-storage-limits-browser.mjs`. They are part of `make test`.
