# Backup metadata and source-binlog write volume

Frequent backups previously rewrote a serialized job option containing two copies of the growing incremental archive catalog for almost every progress change. Credential snapshots were also encrypted again during each save. Separately, database history persisted the growing PITR recovery-point and download catalogs even though the local PITR index already owned that information.

In the investigated 59-second log, the raw source file was 180,400,828 bytes. Job-state row images accounted for 106,444,894 bytes, history row images for 11,778,637 bytes, and MariaDB SQL annotations for 61,465,884 bytes. These were database writes generated by backup bookkeeping on a mostly idle site.

## Persistence changes

- Large `previous_backup_files_array` and `backup_files_array` values are stored as immutable, content-addressed checkpoint records. Identical lists share one record within the job. The job option holds small references, so progress writes do not rewrite the archive catalog.
- Checkpoint records use compact, non-autoloading site/network options. New versions are written and verified before references are published in the parent job option. An interrupted or failed parent write leaves its prior checkpoint usable. Reads verify the job binding, decoded length and SHA-256, and fail on missing or corrupt data.
- Credential ciphertext is reused only after authenticating it under the same job/context, confirming the unchanged plaintext and checking the active key. Changed credentials and key rotation produce new authenticated envelopes.
- An unchanged job save emits no SQL update. Every changed progress checkpoint remains durable.
- Database history stores the PITR chain identity/state; recovery-point, coordinate and download catalogs are reconstructed from the verified local index. A normal PITR increment can leave the database history option unchanged while new recovery points remain discoverable.
- Existing inline job records remain readable and migrate when saved. Checkpoint versions are removed when the parent job is deleted. The scheduled temporary-file sweep collects parts older than 24 hours whose parent never became durable. Ordinary SQL dumps exclude checkpoint records together with their parent job records. Credential fields remain in the job's existing encrypted containers and participate in credential-key maintenance.

## Measured regression workload

The WordPress fixture runs 80 progress updates against a 500-archive incremental chain, comparing the previous persistence pattern with the current job API. It measures the database's `Binlog_bytes_written` counter, along with SQL mutation sizes. The current measurement includes initial checkpoint creation.

| Measurement | Previous pattern | Current |
| --- | ---: | ---: |
| Actual raw source-binlog bytes written | 28,500,854 | 188,592 |
| SQL mutation text bytes | 9,752,689 | 65,142 |
| SQL writes, including initialization | 80 | 82 |

The raw source-binlog reduction was **99.34%** for this workload. This measures bytes written before archive compression. The fixture also verifies resumption, deduplication, no-op saves, failed parent commits, corrupt/missing checkpoints, legacy inline records, job binding and cleanup. Sizes depend on the archive catalog and other database activity.

Run on a disposable WordPress test site:

```sh
podman exec backupplus-test-2-wordpress wp --skip-plugins=backupplus eval-file \
  wp-content/plugins/backupplus/scripts/check-jobdata-write-volume.php
```

It is also part of `make test`. Native MySQL/MariaDB recovery checks verify that compact history reconstructs both the full snapshot and subsequent recovery points without rewriting their derived catalogs into SQL history.

This change preserves native binlog events, database logging settings and PITR replay semantics. Existing source-binlog files retain their current sizes and expire according to the database server's policy. [Archive compression](archive-compression.md) continues to reduce stored and transferred backup sizes independently.
